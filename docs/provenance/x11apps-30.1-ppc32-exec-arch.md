# X11apps 30.1: restore PPC32 executable selection

Target: Apple's exact [X11apps-30.1](https://github.com/apple-oss-distributions/X11apps/tree/X11apps-30.1) source, tag commit `0c764f59596b10773f667b7cc660d366cd8e0150`, tree `43531ce33f61a37652542c59433542890b986566`, included in the repository's 10.6.8 release snapshot. Before this change the working tree and pristine release snapshot had the same Git tree identity. Existing Apple and X.Org license notices remain in place.

Predecessor: Apple's [X11apps-14.3](https://github.com/apple-oss-distributions/X11apps/tree/X11apps-14.3), commit `bb51efb0e77b3d46b8a845de5df201541e7b14c1`, tree `211e9d0ff496ac04be118b2a23801ec4a180831c`, selects all non-64-bit architectures from `RC_ARCHS` for executables. The 30/30.1 source introduced a `MACOSFORGE_RELEASE` branch: `YES` still selects 32-bit architectures, but the ordinary branch rejects every architecture matching `ppc`. Thus `RC_ARCHS=ppc` gives no explicit `-arch ppc` in `CFLAGS` or `LDFLAGS` on that path. The build script passes those flags to its X11 application subprojects. This is an architecture-selection defect for the 10.6.8 PPC32 source target, not evidence of a tested binary failure.

Correction: change only the ordinary branch exclusion from `/ppc/` to `/ppc64/`. This includes `ppc` and keeps the branch's `i386` and `x86_64` selections, while still excluding `ppc64`. The `MACOSFORGE_RELEASE=YES` branch and other build behavior remain unchanged. Exact delta: `patches/X11apps-30.1-ppc32-exec-arch.patch`; manifest: `patches/X11apps-30.1-ppc32-exec-arch.json`. The pristine `src/releases/10.6.8/X11apps-30.1/` snapshot is unchanged.

`tests/test_x11apps_ppc32_exec_arch.py` checks the exact release-to-working delta and patch bytes, parses the two architecture filters, and verifies the selected architectures and flag consumers. The `source-graph` workflow runs that Python source-only test. No compilation, linking, build tool, or hardware test was performed. X11 library, protocol, font and server dependencies require separate source review; PPC runtime compatibility remains unverified.
