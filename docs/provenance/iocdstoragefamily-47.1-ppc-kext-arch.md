# IOCDStorageFamily-47.1 native KEXT PPC architecture

The 10.6.8 release manifest names Apple's [`IOCDStorageFamily-47.1`](https://github.com/apple-oss-distributions/IOCDStorageFamily/tree/IOCDStorageFamily-47.1), annotated tag `c9f11cf82edc8cd3811645418674b4159d5c9837`, commit `48d8b85a220d7edb0b1ef8c0a1371012585bfbf2`. The pristine `src/releases/10.6.8/IOCDStorageFamily-47.1/IOCDStorageFamily.xcodeproj/project.pbxproj` has Git blob `e639234d6deb3dfc543aa3130a0b8c1cef936f99`, matching the Apple tag. Apple's PPC-compatible 10.5.8 predecessor is [`IOCDStorageFamily-39`](https://github.com/apple-oss-distributions/IOCDStorageFamily/tree/IOCDStorageFamily-39), annotated tag `1d2463d267030172252e64c41cc6518d989e4fb0`, commit `0f62379cdd52912bc039198f1431b1f7b741bc9f`. The Apple license remains in the component source.

The 47.1 source retains the predecessor's big-endian `IOCDTypes.h` branches and 32-bit `!__LP64__` driver paths while adding Snow Leopard storage interfaces and 32/64-bit user ioctl layouts. A wholesale predecessor rollback would lose those later interfaces. The existing `IOCDStorageFamily-47.1-ppc-arch.patch` sets `ARCHS = ppc` only on the **Headers** aggregate target, despite its older metadata describing a project-wide change. The `IOCDStorageFamily` native KEXT target has separate Debug and Release configurations (`60218FA5...` and `60218FA6...`), both without `ARCHS`; the project configurations are empty. Header architecture selection therefore does not select the KEXT's architecture.

[`patches/IOCDStorageFamily-47.1-ppc-kext-arch.patch`](../../patches/IOCDStorageFamily-47.1-ppc-kext-arch.patch) adds `ARCHS = ppc` to those two native-target configurations in `src/powerpc/`. It is the exact two-line delta from the pre-existing PPC working file, not a change to the pristine release snapshot. The earlier headers patch remains intact. `tests/test_iocd_kext_ppc_arch.py` pins the official project blob, checks the complete working-file delta and target association, and checks the incremental patch text. Its dedicated CI workflow runs Python source checks only. No compilation, linking, build tools, binaries, or hardware validation were used; KEXT load and media behavior remain unverified.
