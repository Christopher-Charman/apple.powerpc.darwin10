# BerkeleyDB-18: PowerPC test-and-set mutex correction

**Target:** Darwin 10.6.8 PPC32/PPC64 working source `src/powerpc/BerkeleyDB-18/db/dbinc/mutex_int.h`. The first-party `source-releases/10.6.8.json` lists `BerkeleyDB-18`. The pristine `src/releases/10.6.8/BerkeleyDB-18` and pre-change working component both have Git tree `81bb3b26d8f03211a522932403c4df958afd2b93`; the pristine header blob is `79e42bf99905748e0720c578c31ed3654ca78fe2`. No release snapshot is edited.

**Upstream and predecessor:** Apple's [BerkeleyDB-18 tag](https://github.com/apple-oss-distributions/BerkeleyDB/tree/BerkeleyDB-18) is commit `8d01a3629b7b6d5aab223d5d281e9dc44f4d0715` and has the same project tree. Apple's earlier [BerkeleyDB-15 tag](https://github.com/apple-oss-distributions/BerkeleyDB/tree/BerkeleyDB-15) is commit `71261e96a9ec932e41db751280746a8a7d3d5ee5`; its `db/dbinc/mutex.h` blob `88a04ec408face8f566ca00d25d2544b23fe451b` has the same PowerPC `lwarx`/`stwcx.` implementation and defect. The header retains Oracle's license notice. The predecessor establishes PPC source lineage, not correctness of this instruction sequence.

**Defect:** The `HAVE_MUTEX_PPC_GCC_ASSEMBLY` fallback loads a 32-bit lock word but passes the pointer register as both the `stwcx.` value and address. It therefore stores the low 32 bits of the pointer instead of the documented lock value 1. It also casts that pointer to `int` as its acquisition result. On PPC64 an address with zero low 32 bits can leave an acquired lock clear and report failure; even on PPC32 the lock contains an address-derived value. `dist/aclocal/mutex.m4` can select this PPC fallback when its earlier pthread and Darwin spin-lock probes do not provide a mutex. No claim is made that stock 10.6.8 uses this fallback by default.

**Correction:** Keep the pointer only as the memory address, load 1 into the distinct result register before `stwcx.`, retry a failed conditional store, run `isync` only after a successful store, and return 0 when the word was already locked. Use the declared `tsl_t *` lock-word type. The existing release `sync` and zero store remain unchanged. The exact source diff is `patches/BerkeleyDB-18-ppc-mutex.patch`; its companion manifest pins the release tree.

**Verification:** `python3 -m unittest discover -s tests -p 'test_berkeleydb_ppc_mutex.py' -v` checks the immutable Apple blob, exact source diff, assembly register and branch order, release barrier, and a PPC64 low-word-zero address fixture. These are static source tests only. No compilation, linking, build tool, CI compilation or hardware execution was performed. The fallback still needs PPC32/PPC64 ABI and runtime validation before a system-level claim.
