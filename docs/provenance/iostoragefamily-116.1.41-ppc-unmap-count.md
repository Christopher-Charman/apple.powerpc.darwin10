# IOStorageFamily-116.1.41: bound DKIOCUNMAP extents on PPC32

**Target and provenance:** The first-party `source-releases/10.6.8.json` lists `IOStorageFamily-116.1.41`. Apple's [tag](https://github.com/apple-oss-distributions/IOStorageFamily/tree/IOStorageFamily-116.1.41) resolves to commit `3c028686fe4475bb86f25713bd5f736c7354ecac`. The pristine `src/releases/10.6.8/IOStorageFamily-116.1.41` tree is `c04a62175aea17a0c46a086ab91fa3e8aeab4cc5`; its `IOMediaBSDClient.cpp` blob is `6972e0e762ded99b7c94fe8628d8c456a4412299`. The working copy had the same source blob before this correction. The existing project-wide `ARCHS = ppc` patch remains separate. No release snapshot is edited.

**Predecessors:** The official 10.5.8 PowerPC release member is Apple's [IOStorageFamily-92.9](https://github.com/apple-oss-distributions/IOStorageFamily/tree/IOStorageFamily-92.9), commit `8cde8b0dd3b4b99b159bad970e8fd9accc5d71ae`. The nearer [116.1.20](https://github.com/apple-oss-distributions/IOStorageFamily/tree/IOStorageFamily-116.1.20), commit `bf1352ef0355c0634cdd05dc765b6d70d9ad4683`, also lacks `DKIOCUNMAP`. The new path appears in 116.1.41; the earlier code cannot simply be restored because it lacks the 10.6.8 unmap interface.

**Contract and defect:** The exact 10.6.8 [XNU disk header](https://github.com/apple-oss-distributions/xnu/blob/xnu-1504.15.3/bsd/sys/disk.h) declares a 32-bit `dk_unmap_t.extentsCount` and a two-`uint64_t` `dk_extent_t`. `IOStorageExtent` likewise has two `UInt64` fields. XNU's [IONew macro](https://github.com/apple-oss-distributions/xnu/blob/xnu-1504.15.3/iokit/IOKit/IOLib.h) multiplies `sizeof(type) * number` for `IOMalloc`. On a 32-bit PPC kernel, counts above `0x0FFFFFFF` wrap that 16-byte product. For example, `0x10000001` extents request only 16 bytes after 32-bit wrap while the original count reaches `unmap`; this can read past the allocation. This is a source-level risk, not an observed exploit or hardware failure. A 64-bit kernel does not have this specific multiplication wrap for a 32-bit count.

**Correction:** Reject counts above `0xFFFFFFFFU / sizeof(IOStorageExtent)` with `EINVAL` before `IONew`, `copyin`/`bcopy`, and `unmap`. This preserves all nonoverflowing requests and the 10.6.8 interface. The one-hunk exact source diff is `patches/IOStorageFamily-116.1.41-ppc-unmap-count.patch`, with a pinned JSON companion.

**Source-only verification:** `python3 -m unittest discover -s tests -p 'test_iostoragefamily_ppc_unmap_count.py' -v` checks the pristine blob, exact patch, XNU allocation and ioctl contracts, guard placement, and 32-bit wrap boundary. The dedicated CI workflow runs this Python test only. No compilation, linking, build tools, CI compilation, or hardware execution are authorized or claimed. PPC storage ABI and boot behavior remain unverified.
