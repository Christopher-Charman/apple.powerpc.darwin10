# BootCache-64.2: preserve the 64-bit disk read limit on PowerPC

**Target:** Darwin 10.6.8 PPC32/PPC64 working source `src/powerpc/BootCache-64.2/kext.c`. The first-party `source-releases/10.6.8.json` lists `BootCache-64.2`. Apple's [BootCache-64.2 tag](https://github.com/apple-oss-distributions/BootCache/tree/BootCache-64.2) resolves to commit `cbc6a9e59ad4e7d056444c39784d4b263eccca46`. The pristine `src/releases/10.6.8/BootCache-64.2` tree is `4defb3ff35c438f4bfa1592910e410243fd50d9c`; its `kext.c` blob is `6ee5d4c5cde2f72bb5c0f7f664f0df0228692bfd`. The original working blob matched it. No release snapshot is edited.

**Predecessor and contract:** Apple's [BootCache-43.12 tag](https://github.com/apple-oss-distributions/BootCache/tree/BootCache-43.12), commit `0df36ec2ad068d2879f18c9ef49fb9122b850ce3`, is the official 10.5.8 PowerPC release member. It does not issue `DKIOCGETMAXBYTECOUNTREAD`; the limit query enters the BootCache-64 source line. The exact 10.6.8 [XNU disk header](https://github.com/apple-oss-distributions/xnu/blob/xnu-1504.15.3/bsd/sys/disk.h) declares that ioctl as `_IOR('d', 70, uint64_t)`.

**Defect:** `BC_init_cache` supplies an `int` (four bytes) to an ioctl whose output is `uint64_t` (eight bytes). The driver can write four bytes beyond the local object. On big-endian PowerPC, a common limit below 4 GiB occupies the second word of the returned value, so reading only the first word yields zero and the `c_maxread` cap is skipped. The same storage overflow exists on little-endian hosts; its effect depends on stack layout and device response. This is a source-level contract defect, not a measured runtime failure.

**Correction:** Declare `max_byte_count` as `u_int64_t`, matching the neighboring `c_maxread` field and XNU's ioctl output width. The zero initialization, existing limit comparison and fallback logic remain as Apple wrote them. The exact diff is `patches/BootCache-64.2-ppc-ioctl-width.patch`, pinned by its JSON companion.

**Verification:** `python3 -m unittest discover -s tests -p 'test_bootcache_ppc_ioctl_width.py' -v` checks the pristine blob, exact one-hunk patch, XNU ioctl declaration, matching source storage and a big-endian byte-order fixture. These are static source tests only. No compilation, linking, build tools, CI compilation or hardware execution were performed. PPC32/PPC64 ABI and boot behavior remain unverified.
