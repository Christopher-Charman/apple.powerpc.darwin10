# IOFireWireSBP2-406.4.1: PPC32 range conversion scope

**Target and source:** The editable Darwin 10.6.8 source is `src/powerpc/IOFireWireSBP2-406.4.1/IOFireWireSBP2/IOFireWireSBP2ORB.cpp`. Apple's official [IOFireWireSBP2-406.4.1 tag](https://github.com/apple-oss-distributions/IOFireWireSBP2/tree/IOFireWireSBP2-406.4.1) is commit `09ed5528e8319979c2e8a48ef636d2fa1b1d985b`, tree `3c7921ddbe060ea82758334b1ef815224dbd06c8`. That tree matches both the pristine `src/releases/10.6.8/IOFireWireSBP2-406.4.1/` and the working component before this patch; the original ORB file blob is `91bc958b50811de5768e16146a655f57a300e6f7`. Apple license text is retained.

**Predecessor comparison:** The official Leopard 10.5.8 [198.4.0 source](https://github.com/apple-oss-distributions/IOFireWireSBP2/tree/IOFireWireSBP2-198.4.0), commit `f8dc01a91b406ea9d9a79193dc597ce1bfff6b1a`, passed `IOVirtualRange` directly to `IOMemoryDescriptor::withRanges` and did not allocate an intermediate array. The official Snow Leopard 10.6.0 [405.4.0 source](https://github.com/apple-oss-distributions/IOFireWireSBP2/tree/IOFireWireSBP2-405.4.0), commit `857e027067360aef213187797febdbf525fcbb3d`, introduced the `IOAddressRange` conversion with the shadowing declaration; 406.4.1 retains it. The later 420.4.1 Apple tag also retains it, so it is not a corrective donor. The conversion and other Darwin 10 changes remain intact.

**Defect and correction:** The public kernel `IOFireWireSBP2ORB::setCommandBuffersAsRanges(IOVirtualRange *, UInt32, ...)` API declares `address_ranges` as null outside an allocation block, then redeclares it inside the block. For any nonzero count and successful allocation, the subsequent conversion loop indexes the still-null outer pointer. The allocated inner array is also lost at block exit, so the existing cleanup cannot free it. This API is available to PPC32 kernel clients. The SBP2 user-client dispatch separately calls `setCommandBuffersAsRanges64`, so this patch does not claim to repair that route. Assign to the existing outer pointer; the later loop, descriptor call and `IODelete` then use the same array. The exact one-line working-source delta is the adjacent `.patch` file, pinned by the JSON manifest. The pristine release snapshot is untouched.

**Verification:** `python3 -m unittest discover -s tests -p 'test_iofirewiresbp2_ppc_range_shadow.py' -v` checks the Apple blob, exact one-line delta, the 32-bit API's allocation/use/cleanup structure and the separate user-client 64-bit call. This is source-only verification; no compilation, linking or runtime behavior is claimed. PPC hardware and external kernel-client use remain unverified.
