# Libsystem-125.2.11 form-specific libc wrapper scan

Target: the tracked `src/powerpc/Libsystem-125.2.11/libsys/build-libc.pl` from Apple's 10.6.8 `Libsystem-125.2.11` tag (`f490886ee986bdacdd5c1843ebd804edba5904bf`). Its pristine copy remains at `src/releases/10.6.8/Libsystem-125.2.11/libsys/build-libc.pl`, Git blob `f74a0300ec189ef597f09dacc1f70e16666ec884`. Apple source: <https://github.com/apple-oss-distributions/Libsystem/blob/Libsystem-125.2.11/libsys/build-libc.pl>.

`libsys/Makefile` loops over architecture and form, selects `libc-partial$(SUFFIX$(F)).a`, and calls `build-libc.pl` with an output directory ending in `/arch/form`. The MacOSX platform enables debug and profile forms. The script derives the matching form suffix (`_debug`, empty, `_profile`) but `processLibc` always queries `libc-partial.a` with `nm`. It therefore decides which syscall wrapper aliases to omit using the dynamic archive even while generating debug or profile archives. This is incorrect when a form's wrapper set differs, including for `ppc` or `ppc64` in `RC_ARCHS`; it does not establish that the shipped archives differ.

Apple's PowerPC-compatible `Libsystem-111.1.4` script (`11d5fd6aa943b97e878d18bb8c7ee4f427141bdc`) passed the form suffix to `processLibc` and queried `libc-partial$sufname.a`: <https://github.com/apple-oss-distributions/Libsystem/blob/Libsystem-111.1.4/libsys/build-libc.pl>. The regression is already present in the `Libsystem-125` and `Libsystem-125.2.10` tags. Restore only that form selection in the 10.6.8 working source; retain Snow Leopard's `NM` variable and all other successor logic. Exact change: `patches/Libsystem-125.2.11-ppc-form-archive.patch`; pinned review manifest: `patches/Libsystem-125.2.11-ppc-form-archive.json`.

`tests/test_libsystem_ppc_form_archive.py` verifies the untouched Apple blob, exact two-hunk patch, form-to-archive mapping and calling Makefile path using source text only. No compilation, build tool, archive inspection, linker invocation or hardware test was performed. Runtime compatibility remains unverified.
