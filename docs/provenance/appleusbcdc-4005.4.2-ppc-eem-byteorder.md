# AppleUSBCDCDriver-4005.4.2: PPC-safe EEM header byte order

**Target:** `src/powerpc/AppleUSBCDCDriver-4005.4.2/AppleUSBCDCEEM/Classes/AppleUSBCDCEEM.cpp` on Darwin 10.6.8 PowerPC. This changes only the editable working tree. The pristine `src/releases/10.6.8/` copy remains at Git tree `7e3465bf5d0300d5e0d8e4716abd95bc2014eb90`; its EEM source blob is `015757871a1457c800716e9ad20629d9c8e08131`.

**Upstream:** Apple's [AppleUSBCDCDriver-4005.4.2 tag](https://github.com/apple-oss-distributions/AppleUSBCDCDriver/tree/AppleUSBCDCDriver-4005.4.2) at commit `f143664193a071500bf04cfd83f0fb3e0f05ebb2` exactly matches the release snapshot. The [4002.4.1 predecessor](https://github.com/apple-oss-distributions/AppleUSBCDCDriver/tree/AppleUSBCDCDriver-4002.4.1) at `9cf9226607defc048f1835465c5cf6bdba5fe7fc` has identical C++ and header blobs and explicitly includes `ppc` in its target architecture lists. The older [3310.4.1 predecessor](https://github.com/apple-oss-distributions/AppleUSBCDCDriver/tree/AppleUSBCDCDriver-3310.4.1) at `261386964928b1808394b94352060505fd02dbf4` also includes `ppc`. The 4005.4.2 working project already restores `ARCHS = ppc` in its three project configurations; this patch addresses a source defect left by that architecture selection.

**Defect:** The receive completion stores two one-byte EEM header fields through `UInt16 *EEMHeaderAddress`, with the second store writing beyond the `UInt16 EEMHeader` object. The resulting header is not decoded from both wire bytes, and the expression is unsafe regardless of host architecture. The command transmit path copies a host-endian `UInt16` directly to the USB output buffer, producing reversed bytes on big-endian PowerPC. The [USB-IF CDC EEM 1.0 specification](https://www.usb.org/sites/default/files/CDC_EEM10.pdf), section 5.1.2, defines a two-byte EEM packet header. The [Linux upstream CDC EEM driver](https://github.com/torvalds/linux/blob/master/drivers/net/usb/cdc_eem.c) uses `get_unaligned_le16` and `put_unaligned_le16` for this header. Darwin 10.6.8's `libkern/libkern/OSByteOrder.h` supplies `OSReadLittleInt16` and `OSWriteLittleInt16` with PPC byte swapping.

**Correction:** Read the two-byte header with `OSReadLittleInt16` at the receive offset and write the command header with `OSWriteLittleInt16` at output offset zero. The exact unified diff is `patches/AppleUSBCDCDriver-4005.4.2-ppc-eem-byteorder.patch`. No other EEM framing logic, dependencies, release source, license or project architecture setting changes.

**Source-only verification:** `python3 -m unittest discover -s tests -p 'test_appleusbcdc_eem_ppc_byteorder.py' -v` pins the pristine blob, asserts the exact working-source delta and Darwin helper definitions, and checks a representative little-endian wire header. Patch-gate metadata is in `patches/AppleUSBCDCDriver-4005.4.2-ppc-eem-byteorder.json`. No compilation, link, build, CI compilation or hardware test is claimed. EEM packet parsing and end-to-end USB networking still require later review and hardware validation.
