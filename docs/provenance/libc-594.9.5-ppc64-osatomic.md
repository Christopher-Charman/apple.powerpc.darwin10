# Libc-594.9.5 PPC64 OSAtomic 32-bit return values

The official Apple 10.6.8 release lists `Libc-594.9.5` in `source-releases/10.6.8.json`. The immutable release source is `src/releases/10.6.8/Libc-594.9.5/` (component tree `c577656a4766b334a0c8e0d6bc8dbd68c2bb4ae0`); its `ppc/sys/OSAtomic.s` is blob `24858e901e314c389dfaa153470ef83c30da571b`. The PowerPC working source had the same component tree before this correction. Apple’s official 10.5.8 `Libc-498.1.7` is listed in `source-releases/10.5.8.json` and preserved at `src/releases/10.5/Libc-498.1.7/` (tree `177471012991fe2ecc981bfe11932782291ecb0a`).

`ppc64/sys/Makefile.inc` searches `ppc/sys` for `OSAtomic.s`; there is no PPC64-specific file. The 10.6.8 source (already present in Libc-583) uses a direct commpage branch for `_OSAtomicAdd32` and a plain register move after `_OSAtomicAdd32Barrier`. Those paths return signed 32-bit values through a 64-bit PPC64 register without explicitly extending bit 31. Apple’s PPC-compatible 10.5.8 source has separate PPC32 and PPC64 branches: PPC64 calls the commpage and applies `extsw r3,r3`, while the barrier path applies `extsw r3,r4`. Restore exactly those two predecessor sections in the working source. The PPC32 paths and all other atomic operations remain as in 10.6.8. This is a narrow ABI source correction, not a general rollback of later Libc changes.

Exact working-source diff: `patches/Libc-594.9.5-ppc64-osatomic.patch`. `tests/test_libc_ppc64_osatomic.py` checks the pristine blob, exact two-hunk patch, PPC64 source selection, and equality of the restored entry points with the Apple predecessor. It runs as a source-script test in the dedicated `libc-ppc64-osatomic-source` workflow. No compilation, linking, build probe, or hardware validation was performed; runtime behaviour remains unverified.
