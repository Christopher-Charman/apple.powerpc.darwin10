# IOFireWireFamily-426.4.1 PPC64 user library plugin

The official Mac OS X 10.6.8 release manifest names [IOFireWireFamily-426.4.1](https://github.com/apple-oss-distributions/IOFireWireFamily/tree/IOFireWireFamily-426.4.1), annotated tag `27a320295a38e58e9cf9f178a5aa8c2083d4b400`, commit `b8d6ba125afd4cba89ac66eb19d854bbb456923b`. Its pristine tree at `src/releases/10.6.8/IOFireWireFamily-426.4.1/` has Git tree `26cae0d41edc63ce6cd26fd6aedc671711bf78a4`; the project file blob `1abdf348a65a577863cdb50eaae8ddc6d940b209` matches the official Apple tag. That snapshot remains unchanged.

The official PPC Leopard 10.5.8 release manifest names [IOFireWireFamily-349.4.0](https://github.com/apple-oss-distributions/IOFireWireFamily/tree/IOFireWireFamily-349.4.0), annotated tag `f47dfc0c2088ade53780e9c8b839ae49a5b08648`, commit `adbda5f7e483322406a31697bdc1037deeb5f229`. Its project file blob `7a4325384fadfb0fb5fabab26ce53eac0360e509` includes `ppc64` in all four `IOFireWireLib.plugin` configurations. Apple removed those entries by `IOFireWireFamily-417.4.0`, while retaining `ppc`, then shipped the same omission in 426.4.1. The 10.6.8 user library retains `__LP64__` handling and `mach_vm_address_t` fields. The project still defines the `IOFireWireLib.plugin` user-space bundle target. An explicitly selected PPC64 consumer cannot receive a PPC64 plugin slice from the released architecture settings.

[The exact patch](../../patches/IOFireWireFamily-426.4.1-ppc64-plugin.patch) adds `ppc64` after `ppc` in the Development, Deployment, FireLog, and Default configurations of `IOFireWireLib.plugin` only. Later source changes and x86 settings remain intact. The FireWire kernel extension target is untouched. The companion manifest pins the pristine source tree. `tests/test_iofirewirefamily_ppc64_plugin.py` verifies the official file blob, exact four-line working delta, plugin target wiring, and exact patch text. CI runs only this Python source test. No compilation, linking, build tool, binary inspection, or hardware test was run; PPC64 SDK/framework closure and runtime compatibility remain unverified.
