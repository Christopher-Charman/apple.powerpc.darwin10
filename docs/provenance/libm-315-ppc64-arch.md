# Libm-315 desktop PPC64 architecture restoration

The official [Mac OS X 10.6.8 release manifest](../../source-releases/10.6.8.json) names [Apple Libm-315](https://github.com/apple-oss-distributions/Libm/tree/Libm-315), commit `845f432413a66ea992f4797c66157c9824421719`. Its Git tree is `f8b70b4fcea0a66c766359cd58f3b50329b90aad`; the pristine `src/releases/10.6.8/Libm-315/` and initial `src/powerpc/Libm-315/` trees match it exactly. The official project file blob is `6c528fb180814171f0c38889e53e31b3b55b51b8`. The release snapshot remains unchanged.

[Apple Libm-292.4](https://github.com/apple-oss-distributions/Libm/tree/Libm-292.4), commit `d9d7b69507796c31e17089f3aaedde1716a6002b`, tree `ed48b20ee3515f2039fd412d449ce1335b0a67a9`, includes `ppc64` in the desktop project `ARCHS` and `VALID_ARCHS` settings, plus PPC64 source, header, export and compiler settings. Libm-315 removes those project settings and excludes PPC64 from the eight desktop target configurations that override `VALID_ARCHS`. It still retains `Source/PowerPC/`, `Exports/libm_ppc64.a.exp`, PPC64-specific export overrides and PPC64 symbol naming in its source. Thus selecting PPC64 on the unmodified 10.6.8 project cannot produce a PPC64 Libm slice even though the implementation and exports remain available.

[The exact patch](../../patches/Libm-315-ppc64-arch.patch) restores the predecessor PPC64 project settings in the desktop Debug and Default configurations and adds PPC64 to the eight desktop target `VALID_ARCHS` overrides. Current ARM and Intel settings and the iPhone configuration remain intact. The patch does not revert Apple’s 10.6.8 math implementation or header changes.

`tests/test_libm_ppc64_arch.py` verifies the official project blob, exact working delta and patch, and the restored project and target settings. `.github/workflows/libm-ppc64-source.yml` runs only that Python source test. No compilation, linking, build tool, binary inspection or hardware test was run. PPC64 SDK, Libsystem and runtime compatibility remain unverified.
