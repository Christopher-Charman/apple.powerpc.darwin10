# IODVDStorageFamily-30 native KEXT PPC architecture

The 10.6.8 Apple release manifest names [IODVDStorageFamily-30](https://github.com/apple-oss-distributions/IODVDStorageFamily/tree/IODVDStorageFamily-30), annotated tag `e834e72fff6a93e0688d23244ce91bc7fdce2e43`, commit `ca7442826550335059c2ef890a0948914d7987b5`. The pristine project file at `src/releases/10.6.8/IODVDStorageFamily-30/IODVDStorageFamily.xcodeproj/project.pbxproj` has Git blob `54ac3a2893608802671d1e16aee5f43c04241ba3`, matching that Apple tag. The 10.5.8 PPC predecessor is [IODVDStorageFamily-26](https://github.com/apple-oss-distributions/IODVDStorageFamily/tree/IODVDStorageFamily-26), annotated tag `c4dcc9da6218f7663002eab7384a85b73972f92a`, commit `725f9c622c19aa56f883aa24b445ba5389a9e236`. Apple license notices remain in source.

The 30 source retains the predecessor's big endian DVD bitfield branches and 32 bit driver paths. It also adds `__LP64__` types and reserved-slot handling for the later interface. Those changes are retained. The existing `IODVDStorageFamily-30-ppc-arch.patch` sets `ARCHS = ppc` on the **Headers** aggregate target's Debug and Release configurations only, despite its metadata describing project-wide selection. The native `IODVDStorageFamily` KEXT target has separate Debug and Release configurations (`60218F94...` and `60218F95...`), both without `ARCHS`; project configurations are empty. The headers setting therefore does not select the native KEXT architecture.

[The incremental patch](../../patches/IODVDStorageFamily-30-ppc-kext-arch.patch) adds `ARCHS = ppc` to those two native-target configurations in `src/powerpc/`. It is the exact two-line delta from the prior working file. The pristine Apple release snapshot and earlier headers patch remain unchanged. `tests/test_iodvd_kext_ppc_arch.py` pins the official project blob and verifies the complete working-file delta, native target association, and exact patch text. The dedicated CI workflow runs Python source checks only. No compilation, linking, build tools, binaries, or hardware validation were used; KEXT load and DVD media behavior remain unverified.
