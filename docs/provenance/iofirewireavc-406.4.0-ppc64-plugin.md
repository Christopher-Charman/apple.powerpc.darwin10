# IOFireWireAVC-406.4.0 PPC64 user space plugin

The official 10.6.8 release manifest names [IOFireWireAVC-406.4.0](https://github.com/apple-oss-distributions/IOFireWireAVC/tree/IOFireWireAVC-406.4.0), annotated tag `c5f8d5a972d33f5792205b8cb1c882d3d166a28f`, commit `6869f4c5787323a9b70ab04ce699caa1d615002f`. The pristine component at `src/releases/10.6.8/IOFireWireAVC-406.4.0/` has Git tree `3b421691f7d11c45d078061e32e109e9bdb4597c`; its project file has Git blob `1b04a38042ee90e893b9219de18be996e3e5e0f7`, matching the official Apple tag. It remains unchanged.

The official PPC Leopard 10.5.8 predecessor is [IOFireWireAVC-223.4.1](https://github.com/apple-oss-distributions/IOFireWireAVC/tree/IOFireWireAVC-223.4.1), annotated tag `e2b10b4d3441597db8579d7bfda8313aec993cfa`, commit `768b9f31955a1d011f4dfd9cc5f00f35feeec570`. Its project file has Git blob `d1267260061fd35f186e03618d608db59881737b`. Apple retained `ppc64` in all four `IOFireWireAVCLib` configurations there, then removed it from all four in 406.4.0. The 10.6.8 plugin configurations still list `ppc`, `i386`, and `x86_64`, and the native target produces the user space `IOFireWireAVCLib.plugin` bundle with IOKit and CoreFoundation framework dependencies. An explicitly selected PPC64 consumer cannot receive a PPC64 slice from those settings.

[The exact patch](../../patches/IOFireWireAVC-406.4.0-ppc64-plugin.patch) restores `ppc64` after `ppc` in the Development, Deployment, FireLog, and Default configurations of the plugin target only. It retains later 10.6.8 code, x86 settings, and all kernel KEXT settings. The companion manifest pins the pristine tree. `tests/test_iofirewireavc_ppc64_plugin.py` checks the official blob, exact working source delta, native plugin target wiring, four architecture entries, and exact patch text. A dedicated CI workflow runs only this Python source test. No compile, link, build tool, binary, or hardware test was run; PPC64 SDK/framework closure and runtime compatibility remain unverified.
