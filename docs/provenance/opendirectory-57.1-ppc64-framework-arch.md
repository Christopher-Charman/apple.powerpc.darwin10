# OpenDirectory 57.1 PowerPC64 framework architecture selection

Target: Darwin 10.6.8 `OpenDirectory-57.1`, the official Apple OSS release member in `source-releases/10.6.8.json`. The unmodified Apple source is the annotated [`OpenDirectory-57.1` tag](https://github.com/apple-oss-distributions/OpenDirectory/tree/OpenDirectory-57.1), resolved commit `5b6709c108f977ada723be7adda221cbebccf2d2` and tree `6a2e43d09ff1e04d6a5040b5ed34c5c3d9259238`. Before this change, both `src/powerpc/OpenDirectory-57.1/` and `src/releases/10.6.8/OpenDirectory-57.1/` had that exact tree. The pristine release tree remains unchanged.

Predecessor: official 10.5.8 [`OpenDirectory-39` tag](https://github.com/apple-oss-distributions/OpenDirectory/tree/OpenDirectory-39), resolved commit `3df82e00cb103edf307a211934c0547026c59c37`, tree `5edd175cb788f24c66abbf2784691f91edc081f6`. Its project file lists `ppc64` in `ARCHS` for the CFOpenDirectory Development, Deployment, and Default targets, and the OpenDirectory Development and Default targets. The 10.6.8 project retains `ppc64` in both framework targets' `VALID_ARCHS` but omits it from every explicit framework `ARCHS` list. The 10.6.8 Deployment OpenDirectory target has no explicit `ARCHS`, leaving its PowerPC64 selection dependent on toolchain defaults.

Correction: restore `ppc64` in those five explicit framework architecture lists and make OpenDirectory Deployment select the same four slices explicitly. Only `src/powerpc/OpenDirectory-57.1/OpenDirectory.xcodeproj/project.pbxproj` changes. The C and Objective-C implementation, including the official 57.1 authentication-buffer correction relative to 57, remains intact. This selects the PPC64 source slice for both the CF subframework and umbrella framework in all three configurations; it does not establish that dependencies, ABI, linking, or runtime operation pass.

Patch: `patches/OpenDirectory-57.1-ppc64-framework-arch.patch` is the exact unified diff against the pristine 10.6.8 project file. Regression: `tests/test_opendirectory_ppc64_framework_arch.py` verifies all six framework configurations, bounds the working-tree delta to the reviewed architecture entries, and checks patch identity. CI runs only this Python source test plus existing source-graph and historical-source-lock checks. No compilation, linking, or build was performed.
