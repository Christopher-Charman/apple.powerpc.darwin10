# CoreOSMakefiles-63 PowerPC Xcode architecture template

`CoreOSMakefiles-63` is the official 10.6.8 member in `source-releases/10.6.8.json`. Apple's [CoreOSMakefiles-63 tag](https://github.com/apple-oss-distributions/CoreOSMakefiles/tree/CoreOSMakefiles-63) resolves to commit `2288db5cb5ef451ba9637523cb284873f5f55670`. The working component before this change and the immutable `src/releases/10.6.8/CoreOSMakefiles-63/` snapshot shared Git tree `b8bd3ab03845f06d71fdd70a330dcc6baddf9d93`; all 31 source blob IDs matched that Apple tag. The affected `Xcode/BSD.xcconfig` blob was `cffdd8b76380cb48d2d0e86b320ab5e53ee161ca`. The existing Apple license and attribution remain intact.

The PPC-compatible [CoreOSMakefiles-52 tag](https://github.com/apple-oss-distributions/CoreOSMakefiles/tree/CoreOSMakefiles-52), commit `4f91a5dcfd3341eecf2a762d0d686d4cbb067f27`, has no `Xcode/BSD.xcconfig`; the official 10.6.0 `CoreOSMakefiles-61` tag, commit `9921e16eb92bd7747a43d44ff14836fd1f17ab23`, also lacks it. The `-63` template adds `ARCHS = $(ARCHS_STANDARD_32_64_BIT);`. The project's 10.6.8 provenance records for `Libnotify-54.3` and `libdispatch-84.5.5` identify this macro as Intel-only in the intended Xcode 3.2 setup. Its expansion depends on the installed Xcode and SDK, so the explicit `ppc` also protects builds where the macro omits it; on earlier toolchains where the macro already includes PPC, the addition is redundant. Apple's [Xcode build setting reference](https://developer.apple.com/library/archive/documentation/DeveloperTools/Reference/XcodeBuildSettingRef/1-Build_Setting_Reference/build_setting_ref.html) defines `ARCHS` as the target architecture list and includes `ppc` among valid architectures.

The working template adds `ppc` ahead of the existing macro, preserving its Intel selections and every other setting. This corrects the source template that `CoreOSMakefiles-63/Makefile` installs into the CoreOS makefile path; it does not rewrite copies already stored in other projects, including `less-22` and `libiconv-30`. Their own PPC source selection needs separate review. The ReleaseControl makefiles already map `ppc` to `powerpc` for configure targets and pass `RC_ARCHS` through, so they are retained. This is a PPC32 architecture-selection correction. It does not establish a working toolchain, PPC64 coverage, successful compilation, linking or hardware runtime.

Exact patch: `patches/CoreOSMakefiles-63-ppc-xcode-arch.patch`. Regression: `tests/test_coreosmakefiles_ppc_xcode_arch.py`, run by `.github/workflows/coreosmakefiles-ppc-source.yml`. The checks compare the complete working file with the pinned pristine file and validate the patch text. They run source-only Python inspection. No build or compiler is invoked.
