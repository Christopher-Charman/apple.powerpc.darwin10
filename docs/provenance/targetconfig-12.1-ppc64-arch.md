Its `MacOSX.plist` defines `ppc64` with `TARGET_CPU_PPC64`, `TARGET_RT_64_BIT`, and `TARGET_RT_BIG_ENDIAN`. The 12.1 plist retains `ppc` but drops that `ppc64` dictionary while preserving x86 and newer 10.6 target conditionals.

Correction: copy only the predecessor's `ppc64` dictionary into `src/powerpc/TargetConfig-12.1/MacOSX.plist`. `tconf.c` obtains `--archs` from `TargetArchitectures`, uses the same dictionary for architecture-specific `--test` and generated header conditionals, and `bin/gcc` consults `tconf --archs` when splitting SDK architectures. Without the dictionary these paths omit or report false for PPC64. The 10.6.8 `TARGET_HAVE_QUARANTINE` and `TARGET_HAVE_SANDBOX` entries and Intel architecture dictionaries remain intact. This declares a PPC64 target; it does not prove an SDK, compiler, link, ABI or runtime path is functional.

The exact working-tree delta is `patches/TargetConfig-12.1-ppc64-arch.patch`; the pristine release snapshot is unchanged. `tests/test_targetconfig_ppc64_arch.py` parses the plist, checks the donor-derived PPC64 values, verifies the complete component differs only by this entry, checks the exact patch, and traces source consumers. The source-only CI workflow runs this test. No compilation, linking, build tools or hardware tests were run.
