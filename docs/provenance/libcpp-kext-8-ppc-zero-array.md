# Libcpp_kext-8: zero-sized nothrow array allocation on PowerPC

- Target: `src/powerpc/Libcpp_kext-8/new_opvnt.cc`, PowerPC Darwin 10.6.8 KEXT C++ support.
- Official Apple 10.6.8 source: [`Libcpp_kext-8`](https://github.com/apple-oss-distributions/Libcpp_kext/tree/Libcpp_kext-8), tag commit `03e204fc796ae1324ef992942a6339c110e48e11`. The pristine file is retained at `src/releases/10.6.8/Libcpp_kext-8/new_opvnt.cc`, Git blob `a86bd0f42a34dc930f6e3eb6d467ecf56665abb7`.
- PPC-compatible predecessor: Apple [`Libcpp_kext-5`](https://github.com/apple-oss-distributions/Libcpp_kext/tree/Libcpp_kext-5), tag commit `01d4170a14555084aa14ef136df6d28f1fc0c05a`. Its scalar nothrow operator already turns zero into one byte. Version 8 retains that behavior in `new_opnt.cc` and its array form in `new_opv.cc`, but leaves the nothrow array form unguarded.
- Consumer contract: pristine [`xnu-1504.15.3/libkern/c++/OSRuntime.cpp`](../../src/releases/10.6.8/xnu-1504.15.3/libkern/c++/OSRuntime.cpp) returns null from `kern_os_malloc(0)`. The `__ppc__`-guarded nothrow array operator in `Libcpp_kext-8` directly passes zero to it, so a zero-sized allocation reports failure despite available memory. The kernel array operator normalizes zero to one byte.
- Exact source correction: inside `operator new[](unsigned long, const std::nothrow_t&)`, insert `if (sz == 0) sz = 1;` before `return kern_os_malloc(sz);`. The dated in-file comment records why. `patches/Libcpp_kext-8-ppc-zero-array.patch` is the exact unified diff from the pinned pristine file. The existing PPC/i386 guard, allocator, license and all other code remain intact.
- Verification: `python3 -m unittest discover -s tests -p test_libcpp_kext_ppc_zero_array.py -v` is source-only. It pins the official blob and exact patch, and checks XNU's zero-size behavior and the scalar/array precedents. The initial two assertions failed against the pristine source; all three tests pass against this correction. The dedicated PR workflow runs only this Python source test. No compilation, linking, build, binary inspection or hardware execution was performed.
- Integration: XNU `kern_os_malloc` is the allocator dependency. This patch changes only the zero-size request passed by the KEXT helper; it does not alter ABI, symbol ownership, or pristine release sources. PPC runtime behavior remains unverified.
