# SmartCardServices-36160: PPC32 reader respawn

**Target and provenance:** The editable source is `src/powerpc/SmartCardServices-36160/src/PCSC/pcscdaemon.c`. Apple's official [SmartCardServices-36160 tag](https://github.com/apple-oss-distributions/SmartCardServices/tree/SmartCardServices-36160) is annotated tag `8a98e0b48ee898f220ba3c794cc71af762dc3796`, commit `13d969e50893e52fab130055170aef624dd01817`, tree `5ad03be15dd61f0cae258aa964d9c2d2221eff92`. The working component's file object IDs matched the pristine `src/releases/10.6.8/SmartCardServices-36160/` before this change; `pcscdaemon.c` is blob `a33281ea8bf27772e1b9393ea094bf5f15e383ca`. Apple's license and the release snapshot remain intact. Apple's 10.6.8 release manifest identifies this exact tag.

**Predecessor comparison:** Apple's [SmartCardServices-34733 tag](https://github.com/apple-oss-distributions/SmartCardServices/tree/SmartCardServices-34733) is the official 10.5.8 PowerPC-era member (commit `c20f826fc881abd95dc0d1f2977fef82f4da91d2`, tree `f0619e725fd2bbf70e2006bd5c6fd5d79bdff6f9`). The [34733-to-36160 comparison](https://github.com/apple-oss-distributions/SmartCardServices/compare/SmartCardServices-34733...SmartCardServices-36160) shows the later daemon added the 32-bit respawn path. The predecessor has no `tryRespawn` or hard-coded i386 preference. This patch retains the 10.6.8 daemon and IPC changes.

**Defect and correction:** In `readerfactory.c`, `ReaderCheckArchitecture` checks a running 64-bit daemon against a reader bundle's executable architectures. When the bundle lacks the current slice, it sends `SIGUSR2`; the daemon's `tryRespawn` sets a spawn preference for **only** `CPU_TYPE_I386`. A PPC64 daemon needing a 32-bit PPC reader thus asks the OS for the wrong CPU family. Under the existing 10.5-minimum deployment condition, select `CPU_TYPE_POWERPC` for PPC source slices and retain `CPU_TYPE_I386` for Intel source slices. The exact one-file working-tree delta is in the companion patch. The source code can reach this branch only when `MAX_OS_X_VERSION_MIN_REQUIRED <= MAX_OS_X_VERSION_10_5`; this patch does not broaden that gate.

**Dependency and limits:** The affected path is pcscd loading a 32-bit reader driver through the existing PCSC reader factory. It changes no IPC structures, public ABI, reader bundle, or install payload. `python3 -m unittest discover -s tests -p 'test_smartcardservices_ppc32_respawn.py' -v` checks the pinned Apple blob, exact source delta and companion patch text, mismatch signal path and PPC versus Intel spawn preference. The dedicated CI workflow runs this source-only test. The existing generic `ppc_patch_gate.py` accepts release-tree patch paths and therefore is not used for this working-tree source patch. No compilation, linkage, reader hardware behavior or actual process respawn is claimed.
