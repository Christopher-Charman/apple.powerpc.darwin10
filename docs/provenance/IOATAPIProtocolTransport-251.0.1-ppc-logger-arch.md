# IOATAPIProtocolTransport-251.0.1 ATAPILogger PPC target

Official Apple 10.6.8 source: [`apple-oss-distributions/IOATAPIProtocolTransport`, tag `IOATAPIProtocolTransport-251.0.1`](https://github.com/apple-oss-distributions/IOATAPIProtocolTransport/tree/IOATAPIProtocolTransport-251.0.1). The pristine project at `src/releases/10.6.8/IOATAPIProtocolTransport-251.0.1/ATAPILogger/ATAPILogger.xcodeproj/project.pbxproj` has Git blob `55e6c098d1c1d01baa75ad3253369bd4adeabaae`, matching the Apple tag. Its license is retained in `APPLE_LICENSE`. The PPC-compatible predecessor is Apple's [`IOATAPIProtocolTransport-250.0.6`](https://github.com/apple-oss-distributions/IOATAPIProtocolTransport/tree/IOATAPIProtocolTransport-250.0.6), whose logger Release configuration explicitly included `ppc` and `i386`. The 251.0.1 logger changed Debug and Release to the `ARCHS_STANDARD_32_64_BIT_PRE_XCODE_3_1` macro, set to `x86_64 i386 ppc` in both target configurations.

The 251.0.1 transport C++ and headers are unchanged from that predecessor. The editable 251.0.1 kext already pins all three configurations to `ARCHS = ppc` under the separate `IOATAPIProtocolTransport-251.0.1-ppc-arch.patch`; its project declares ATAPILogger as a target dependency. The logger's two configurations still request Intel slices. Pin both logger target `ARCHS` values to `ppc` so the bundled diagnostic tool selects the same PPC32 target as its parent kext. Leave the standard-architecture macro and `VALID_ARCHS` declarations intact; explicit target `ARCHS` now selects the desired member. The exact two-line source delta from the pristine logger project is [`patches/IOATAPIProtocolTransport-251.0.1-ppc-logger-arch.patch`](../../patches/IOATAPIProtocolTransport-251.0.1-ppc-logger-arch.patch).

`tests/test_ioatapi_logger_ppc_arch.py` checks the official release blob, exact working-source delta, parent target dependency, and patch text. It runs as a source-only CI job. No compilation, linking, build tools, binaries, or hardware tests were used. Compatibility of `reexec_to_match_kernel`, private headers, SDK availability, and runtime logger behavior remain unverified.
